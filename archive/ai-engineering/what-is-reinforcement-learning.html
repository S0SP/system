1. What is Reinforcement learning?

Let’s start with the definition of Reinforcement Learning (RL).

RL is a type of machine learning (besides Supervised and Unsupervised learning) that deals with an entity called an ‘Agent’, trying to learn to perform a task better in its ‘Environment’ through trial and error.

For example, a deer (Agent) foraging in a forest (Environment) to survive, avoiding being eaten by its predators.

We will soon move to more AI-related examples, I promise, but first, let’s better understand what the terms ‘Agent’ and ‘Environment’ mean.

2. Agent

An agent is the central entity in RL.

It is one that studies and interacts with its environment, makes decisions, takes actions, and learns from its outcomes.

In our previous case, we used a deer as an agent example, but from now on, we will discuss concepts assuming an LLM as the agent as well.

3. Environment

The environment is everything outside the agent with which it interacts.

The function of an environment is to:

  • Get affected by an agent’s actions

  • Change its state (or maybe hold its state constant) depending on the agent’s actions

  • Give the agent a reward or punishment based on its actions, so that the agent can modify its intent the next time it takes an action

In the first case, the deer was functioning in a forest as its environment. Based on the deer’s actions (moving around in different directions), either the forest (environment) lets it progress towards food (reward) or it exposes it to a cheetah (punishment).

In the case of an LLM as an agent, everything outside it, such as the following, is part of its environment:

  • User inputs

  • System prompt

  • Tools / APIs it can call

  • System responses (tool results, API outputs, error messages)

  • Context (documents, conversation history, files)

4. State

A State is a snapshot of an environment at a time. It is everything an agent sees at a given moment that it can use to make its next decision.

For a deer agent, it could be its current location in the forest, nearby predators, and the time of day.

For an LLM agent, it is all the context it has access to at a moment, which it can use to decide its next action.

But what’s action?

5. Action

An action is the choice that an agent makes in a given state of the environment.

For a deer agent, an action could be moving toward a foraging area or running away when it spots a predator.

For an LLM agent, an action could be generating text, creating an image, or calling a tool.

An important point to consider is that the action becomes fine-grained as you zoom in on a scenario.

For example, for a deer, an action could be moving its leg muscles and joints faster as it spots a predator in its environment.

Similarly, generating a single token is an action for an LLM, given all the previous tokens it has generated (environment).

6. Action Space

The action space is the set of all possible actions an agent can take in a given state.

A deer agent’s action space could consist of moving in 4 directions, jumping, eating, or staying still.

An LLM’s action space includes generating different responses and using the available tools.

As we zoom in to the token level and view each token generation as an LLM’s action, the action space becomes the model’s vocabulary (the set of all tokens it can output at a given step).

A deer cannot fly, and an LLM cannot produce a ray of light. An agent can only take actions available within its action space.

7. Reward

A reward is a signal an agent receives from its environment that guides it to take better actions in the future.

Rewards can either be positive, zero, or negative.

RL researchers are considerate people and usually avoid using the term ‘Punishment’ in literature.

For a deer agent:

  • Finding food and escaping a predator will return a positive reward from the environment

  • Taking actions that lead to getting injured or starving will return a negative reward from the environment

For an LLM being trained with Reinforcement Learning from Human Feedback (RLHF):

  • Generating safe and helpful responses returns a positive reward from the environment

  • Generating harmful responses returns a negative reward from the environment

The environment in this case includes a reward model.

We will discuss RLHF in more detail in the upcoming sections, so don’t worry about it just yet.

8. Policy

An agent’s strategy for taking actions in a particular state is called its Policy.

Mathematically, it is a mapping that decides what action to take given a specific state.

A policy can be either:

  • Deterministic: An agent takes the same action if in a specific state

  • Stochastic/Probabilistic: An agent takes different actions in a given state based on probabilities, as with LLMs, where the temperature controls which token it generates next

For a deer agent, its learned survival instincts are its policy.

For an LLM, its parameters (weights and biases) are its policy. Although it’s important to know that in popular RL literature, the LLM is itself considered the policy.

9. Trajectory

A trajectory is the complete sequence of states, actions, and rewards that an agent experiences over time as it interacts with an environment.

Trajectories could be:

  • Finite: For tasks that end, such as for a chess-playing agent

  • Infinite: For tasks that continue indefinitely, such as a stock market trading agent

For a deer agent, a trajectory could look like:

  • Forest in the morning (state)

  • Walk to the river and drink water (action)

  • Receive a reward from the environment, as this action helps in survival (positive reward)

  • Spot a predator (state)

  • Run away (action)

  • Get caught by the predator and die, ending the trajectory (receive a negative reward from the environment)

For an LLM agent being trained to call tools and respond helpfully, a trajectory could look like:

  • LLM is given a query (state)

  • It calls a tool for searching the web (action)

  • It receives a reward for calling the right tool (positive reward)

  • Search results appear (new state)

  • LLM uses the search results to generate a final answer (action)

  • The answer is correct, and the LLM receives a positive reward

10. Episode

An episode is a trajectory with a definite end.

It is a finite sequence of interactions between an agent and its environment from the start to a terminal state.

For example, a deer agent that starts in a quiet forest but ends up being eaten by its predator marks an episode (unfortunately, a very bad one).

Similarly, an LLM agent successfully fulfilling a user’s request to order their favorite meal online represents an episode, as it has a clear start and end.

11. Return

Return is the total reward that an agent gathers over an episode (or even over an indefinite trajectory).

For a deer agent in an episode of a day (from the beginning state of waking up to the terminal state of going to sleep), the return is the sum of all:

  • Positive rewards: for eating food, drinking water, escaping a predator

  • Negative rewards: for getting injured, getting separated from the herd

For an LLM being trained to reason, an episode begins when it is prompted and continues until it reaches a terminal state, at which point it returns its final output.

Its return during this period is the sum of all:

  • Positive rewards: for clear logical reasoning steps, using appropriate tools, and returning a helpful and safe final answer

  • Negative rewards: for making logical errors in its reasoning chain, repetitive reasoning, giving up too early, using the wrong tools, and returning a wrong final answer

The goal of an RL agent is to maximize its return in an environment, which means learning to take actions that get more positive rewards and fewer negative rewards.

12. Discounted Rewards

An agent must take time to explore its environment to maximize return, as being greedy for tiny short-term rewards could lead to missing out on huge long-term rewards.

For example, a deer might focus on foraging in an open grassland (focused on immediate reward), but then be spotted and eaten by its predator (a poor long-term outcome).

But again, the agent must not spend too long exploring the environment and must also exploit the resources available to it.

For example, if grass is available, eating it might help the deer regain its energy and escape its predator if it gets spotted.

This is the classical Exploration–Exploitation dilemma in RL (and in our lives).

To control how an agent behaves in an environment, a discount factor is used when calculating the return.

The Discount Factor (ɣ) is a value between 0 and 1 that controls how much the agent cares about future rewards vs immediate ones.

  • A low ɣ (0.25) increases the value of immediate rewards and makes the agent greedy.

  • A high ɣ (0.99) makes future rewards nearly as valuable as immediate ones, nudging the agent to plan long-term.

Consider a reasoning LLM in training.

A lower discount factor will push the model to reason with shorter, more focused reasoning chains, since we reward them more and heavily discount future rewards.

But again, we can’t make the discount factor too low, as this will cause the LLM to skip longer critical reasoning steps in the hope of a quick reward.

This is the reason finding the sweet spot with discounting rewards is so important.

13. Value Functions

Value functions are mathematical functions that an agent relies on when trying to maximize its return.

These functions estimate how good it is for an agent to be in a specific situation. When we say “how good”, this means the expected future return from a given situation. The expected future return is called Value.

There are three value functions that answer three different things:

(The terms ‘s’ and ‘a’ refer to state and action, respectively.)

  1. State-Value function or V(s): “How good is it for an agent to be in a particular state?”

    For example, for the deer agent, the value of being on a river bank covered with trees (state) is higher than being in the open.

  2. Action-Value function or Q-function or Q(s, a): “How good is it for an agent to be in a particular state and take a particular action from there?”

    For example, for the deer agent, the value of drinking water (action) when near the river bank (state) is higher than moving away (another action).

  3. Advantage function or A(s, a): “How much better is it for an agent in a particular state to take a particular action compared to average?”

    For example, let’s say for the deer agent in the forest (state), the average value across all possible actions is V = 5.

    When it walks to the river, this action in the current state has an action-value of Q = 8, but when it sleeps in the open, the action-value is Q = 1.

    This means:

    • The advantage of walking to the river is Q - V = 8 - 5 = +3

    • The advantage of sleeping in the open is Q - V = 1 - 5 = -4

But how do we actually solve these value functions?

14. Bellman Equation

The Bellman equation defines value functions recursively, making them easy to calculate.

It defines a value function as the sum of the expected immediate reward plus the discounted value of the next state.

Although the following image shows the Bellman equation for the state-value function, both the state-value and the action-value function have their own Bellman equations.

15. Markov Property

Everything that we have described above follows the Markov Property.

This means that the future state depends only on the present state and the action taken from here, rather than on the entire history of the agent and the environment.

In other words, knowing where the agent is right now provides all the information needed to predict its future, rather than knowing how it got here.

16. Markov Decision Process (MDP)

The foundational mathematical framework for decision-making in RL, and for finding the optimal policy that maximizes the expected cumulative discounted reward, is built on the Markov property and is called the Markov Decision Process.

It consists of:

  • States that the agent can be in

  • Actions that the agent can take at each state

  • Transition probability: The probability of moving from one state to another when an action is taken

  • The reward that the agent receives after transitioning from one state to another

  • Discount factor that prioritizes receiving short-term rewards over long-term

All classical RL algorithms assume that the environment is an MDP.

17. RL Algorithms

Till now, we have learned that an agent in an environment:

  • Wants to maximize its return

  • Can evaluate different situations using value functions and the Bellman equations for them

But how does the agent actually learn to act in the most optimal way that maximizes the return?

It can learn to do so in two settings:

  1. Model-based RL: This is where an agent is either given or it builds an internal model of its environment. This model helps the agent plan ahead before acting in the environment.
    Google DeepMind’s AlphaGo is an example of this approach, in which the RL agent is given a model of the game Go that it can use to plan its future moves.

  2. Model-free RL: This is where an agent does not have a model of its environment, or it does not understand how its environment works. The agent interacts with it and learns from experience.

Model-free RL is more widely used and comes in two flavours (or a combination of them):

  1. Value-based methods
    These involve an agent learning optimal (or best) value functions to know how good each state or state–action pair is, and then choosing the highest-value actions based on them.

    Some examples of these methods include:

    • Q-learning/ Deep Q-Network (DQN)

    • SARSA

  2. Policy-based methods

    These involve an agent directly learning the policy that maximizes the return. Such a policy is called the Optimal policy.

    Some examples of these methods include:

    • REINFORCE

    • TRPO

    • PPO

Since we are focusing on RL in relation to LLMs, we will exclusively focus on model-free methods, specifically policy-based methods.

Of these, we are particularly interested in PPO and GRPO.

18. PPO

Proximal Policy Optimization (PPO) comes from a family of policy-based RL algorithms called Policy Gradient.

Here is how Policy Gradient algorithms work:

  • An agent (an LLM in our case) first interacts with its environment and collects samples in its trajectory (a set of states, actions, and rewards). These are used to estimate returns for each action taken.

  • The gradient of expected return with respect to the policy parameters is computed next.

  • Finally, the policy parameters are updated in the direction that increases return.

These steps are repeated over many trajectories, which iteratively improve the policy toward selecting actions that lead to higher rewards.

There’s a small problem with this algorithm, though.

Let’s say that one of the actions leads to a huge reward. This can dramatically change the policy in a single update, sometimes collapsing what the agent has already learned.

For example, if a deer once found lots of food in open ground, a single large reward could cause it to change its behaviour, always looking for food there.

That’s disastrous for the deer because it increases the risk of being spotted by a predator. Instead, it must slowly and gradually update its instincts rather than change them too much in response to a single big reward.

And this is what leads to PPO.

PPO carefully updates an agent’s policy so that the updated policy does not deviate too far from the previous one. (Hence, the term ‘Proximal’ in its name.)

PPO clips each policy update within a range, setting upper and lower limits on how much a policy can change in one go, regardless of how good or bad an action and its resulting reward are.

19. RLHF

The purpose of modern LLMs is not only to generate the next token, but also to follow a user’s instructions helpfully and return a safe response.

Reinforcement Learning from Human Feedback, or RLHF, is one of the techniques introduced by OpenAI that makes this possible.

RLHF fine-tunes an LLM to respond in a way that is aligned with human preferences. Therefore, this fine-tuning technique is also called Alignment-tuning.

Here is how it works:

  1. The process of RLHF starts with an LLM that has been supervised fine-tuned to generate responses to user queries in a conversational style. This differs from a pre-trained LLM that can only generate text but cannot chat with a user.

  2. Multiple responses to different prompts are collected, and a human labels them from most preferred to least preferred.

  3. Based on this preference data, a separate reward model (LLM) is trained to predict which response humans would prefer for a given prompt. This reward model returns a higher reward for a more preferred response and vice versa, serving as a proxy for a human judge.

  4. The LLM, during training, generates a response to a given prompt.

  5. This response is evaluated by the reward model, which returns a reward.

  6. Based on the reward, PPO updates the LLM during training to produce higher-rewarded responses.

The process of RLHF is described briefly here.

It is slightly more complex than this, but it becomes clearer when we return to the PPO image we saw earlier.

Here is how it goes:

  1. Given a prompt or query (Q), the Policy model (the LLM in training) generates a response or output (O).

  2. This output goes to a Reward model, which returns a reward (R) based on how much the response is aligned with human preferences.

  3. Output is also sent to a Reference model (a frozen copy of the original Policy model) and compared with its output, and a KL penalty is calculated based on how much these differ.

  4. This penalty is subtracted from the Reward model’s score/ reward to ensure that the response the reward model highly rewards stays close to the natural human-like outputs that the Reference model is a proxy for.

  5. A Value model also considers the prompt and the response to predict the final reward at each step. This predicted reward or value is represented by V.

  6. The reward (R) and value (V) are used to compute the advantage (A) using the GAE (Generalized Advantage Estimation) method.

  7. The advantage is used to update the Policy model, where each policy update is clipped within a range to avoid big changes.

  8. The Value model is also updated using a separate loss to predict rewards more accurately in the future steps.

RLHF with PPO requires 4 models (Policy, Reference, Reward, and Value), of which the Reward and Reference models have frozen weights, while the Policy and Value models are trained.

This makes it difficult to optimize and very memory-intensive. This is the reason why modern LLM pipelines skip PPO and use either:

  • Group Relative Policy Optimization or GRPO: A simpler and memory-efficient version of PPO that entirely removes the Value model

  • Direct Preference Optimization or DPO: That removes the RL part of RLHF and instead directly trains the LLM on preference pairs using a supervised objective

20. GRPO

Group Relative Policy Optimization, or GRPO, introduced by DeepSeek, simplifies PPO by removing the Value model entirely.

Remember how the Value model was being used to predict if a response was better than expected?

GRPO does this by simply checking if a response was better than the others in the group of generated responses. This makes it more memory-efficient and easier to implement than PPO.

Here is how it works:

  1. For a given prompt or query (Q), the Policy model first generates a group of responses or outputs (O1 to Og) all at once.

  2. Each response is scored by the Reward model, producing rewards (R1 to Rg).

  3. Reference model is used to compute a KL penalty that keeps the Policy model from drifting too far from its starting point.

  4. The average and standard deviation of all rewards are calculated for the group of responses.

  5. These are used to compute an Advantage value for each response (A1 to Ag), which tells how much better or worse it is than the group average.

  6. Policy Model is then updated (using a clipped update) to increase the probability of generating high-advantage responses and reduce the probability of generating low-advantage responses.

21. RLVR

It’s now time to understand the final concept of this lesson called RLVR.

Reinforcement Learning with Verifiable Rewards (RLVR), introduced in the Tulu 3 paper, is a method for training an LLM to perform well on tasks that can be verified objectively.

This includes tasks such as math or coding, where a simpler rule-based verifier (not an LLM) can check whether the answer is correct.

Compare this to tasks such as aligning an LLM with human preferences, which are highly subjective and cannot be handled by RLVR.

This is how it works:

  1. For a given prompt to solve a math/ coding task, the Policy model generates a response(s).

  2. A rule-based verifier checks whether the answer is correct or incorrect. The correct response(s) receive a reward of 1, while the incorrect ones receive 0.

  3. PPO or GRPO is used to update the Policy model and make the correct reasoning paths more likely.

To make it clearer, if RLVR is used with PPO:

  • The policy model generates a single response.

  • It is verified for correctness using a simple verifier (instead of the reward model) that returns a reward.

  • KL penalty between the policy and the reference model is applied to regularize the update.

  • A value model estimates the expected reward, and the advantage is computed.

  • Policy model is updated using a clipped update.

But if RLVR is used with GRPO:

  • The policy model generates a group of responses for a given prompt.

  • These are verified for correctness using a simple verifier that returns rewards.

  • A KL penalty between the policy and the reference model is applied to regularize the update.

  • Mean and standard deviation of the group’s rewards are calculated.

  • The advantage for each response is calculated relative to the group mean and standard deviation.

  • Policy model is updated using a clipped update.

TL;DR

Here are the one-line definitions of all the terms if you’re short on time.

  • Reinforcement Learning: One of the three subtypes of Machine learning, where an agent learns to perform tasks better through trial and error

  • Agent: The central entity and decision maker in RL.

  • Environment: Everything outside the agent that it interacts with and receives feedback from.

  • State: A snapshot of the environment at a given time.

  • Action: A choice that the agent makes in a given state of the environment.

  • Action Space: The set of all possible actions the agent can take in a given state.

  • Reward: A signal (either positive, zero, or negative) that the agent receives from the environment that guides it to take better actions in the future.

  • Policy: The agent’s strategy for taking actions in a particular state.

  • Trajectory: The complete sequence of states, actions, and rewards that an agent experiences over time as it interacts with an environment.

  • Episode: A trajectory that has a definite end.

  • Return: The total reward an agent gathers over its trajectory.

  • Discounted Rewards: A method of weighting rewards so the agent learns to balance short-term gains with long-term planning.

  • Value Functions: Mathematical functions that estimate how good it is for an agent to be in a certain situation or take a certain action, in order to maximize its return.

  • Bellman Equation: A recursive formula that defines a value function as the sum of the expected immediate reward plus the discounted value of the next state, making it easy to compute.

  • Markov Property: The idea that the future state of an agent depends only on the present state and the action taken from there, rather than on the entire history of the agent and the environment.

  • MDP: The foundational mathematical framework for decision-making in RL, built on the Markov property, for finding the optimal policy that maximizes expected cumulative discounted reward.

  • RL Algorithms: The methods that the agent uses to learn to act in the most optimal way that maximizes the return.

  • PPO: A policy gradient algorithm that carefully updates an agent’s policy so that the updated policy does not deviate too far from the previous one.

  • RLHF: A technique that fine-tunes an LLM to respond in a harmless and helpful way that is aligned with human preferences.

  • GRPO: A simpler and memory-efficient version of PPO that removes the Value model and checks if a response was better than the others in a group of generated responses.

  • RLVR: A method for training LLMs on objectively verifiable tasks like math and coding, that replaces the Reward model with a rule-based verifier.
