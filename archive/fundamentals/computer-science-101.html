1. Logic Gates

At the very bottom of every computer you operate is something surprisingly simple.

It’s a switch with two states: on and off.

In a computer, a Transistor acts as a tiny electronic switch that can switch on and off billions of times per second, depending on whether current is flowing through it.

These two states represent binary information where the ‘on’ state represents a binary 1, while the ‘off’ state represents a binary 0.

Multiple transistors are put together to create Logic gates. These are circuits that perform basic Boolean operations on binary inputs and produce a single binary output.

There are seven basic logic gates:

  • AND gate: Outputs 1 only when all inputs are 1

  • OR gate: Outputs 1 if at least one input is 1

  • NOT gate: Inverts the input signal (outputs 1 for 0 and 0 for 1)

  • NAND or NOT-AND gate: Outputs 0 only when all inputs are 1 (inverse of AND gate operation)

  • NOR or NOT-OR gate: Outputs 1 only when all inputs are 0 (inverse of OR gate operation)

  • XOR or Exclusive OR gate: Outputs 1 when inputs are different

  • XNOR or Exclusive NOR gate: Outputs 1 when inputs are the same

A Buffer gate is used with these gates; it takes an input and outputs it unchanged. It is used for signal amplification or isolation.

Logic gates are further combined and integrated onto a single chip (Integrated Circuit, or IC) to perform more complex functions.

A Universal logic gate is one that can be used to construct any other logic gate.

Two logic gates belong to this category:

  • NAND gate

  • NOR gate

This means that any computer, regardless of how complex, can be built using only these gates.

Isn’t that crazy?

A fun fact: The Apollo Guidance Computer (AGC), used to navigate Apollo missions to the Moon, was built almost entirely from simple 3‑input NOR‑gate ICs.

2. The Central Processing Unit (CPU)

The Central Processing Unit (CPU) of a computer is built by combining logic-gate-implementing ICs.

It consists of:

  1. Arithmetic Logic Unit (ALU), which performs mathematical operations (addition, subtraction, multiplication) and logical comparisons (equal to, greater than, less than).

  2. Registers, which are small, ultra-fast memory components built directly into the CPU that hold data mid-calculation and track which instruction to execute next

  3. Control Unit (CU), which acts as an orchestrator that fetches instructions from memory, decodes them, and coordinates data flow between the ALU, registers, and external memory.

A CPU can execute billions of instructions per second using these components and acts as a computer’s brain.

3. Turing Machine

Before we move on to the other layers on top of the physical one (hardware), we need to understand what computation means in theory.

In 1936, Alan Turing described a theoretical machine, called the Turing Machine, which consists of:

  • an infinite tape divided into cells, each holding a symbol

  • a read/write head that moves along the tape, and

  • a set of rules that determines the machine’s behavior based on its current state and the symbol being read

Although purely theoretical (since no physical tape is infinite), the concept of a Turing machine tells us that any complex problem can be solved through a sequence of logical operations.

Furthermore, the Church-Turing thesis states that any problem that can be computed can be computed by a Turing machine and, by extension, any general-purpose computer can solve it given enough time and memory.

Every modern computer is essentially a practical, finite version of the Turing Machine.

4. Programming Languages, Compilers & Interpreters

Since working directly with binary information is tough, additional abstractions are built on top in the form of programming languages.

These languages are translated into binary machine instructions that a CPU can execute. This is done using programs called Compilers and Interpreters.

A Compiler translates the entire source code of a programming language into a binary executable that the CPU can run directly. Some examples of compiled languages are C, C++, Rust, and Go.

These produce fast executables because translation occurs once before runtime, but as a caveat, one must recompile their code for each platform (Windows, Mac, Linux) and recompile after every code change.

Interpreters work differently from this. They read source code, parse it, and execute instructions on the fly without producing a separate executable.

This allows immediate code execution, with the same code running everywhere. The trade-off is that they are typically slower than compiled code because translation happens during execution.

Some examples of interpreted languages are Python, JavaScript, and Ruby.

5. Data Structures

Data structures are ways of organizing data so that programs can use it efficiently.

Some of the most important data structures that you must know about are:

  1. Array

  2. Linked list

  3. Stack

  4. Queue

  5. Hash Table

  6. Tree

  7. Graph

  8. Heap

Let’s discuss them one at a time.

1. Array

An array stores data elements in contiguous memory. This allows indexed access to elements, but arrays are costly to resize and insert elements in the middle.

2. Linked List

A linked list stores data elements as nodes connected by pointers. This enables efficient insertion and deletion operations but slower element access.

3. Stack

A stack follows the Last-In, First-Out (LIFO) principle for inserting and removing data elements.

This means that elements that are in a stack are removed in the reverse order of their insertion.

4. Queue

A queue follows the First-In, First-Out (FIFO) principle for inserting and removing data elements.

This means that elements inserted first are removed first, and those inserted later must wait until all earlier elements have been removed.

5. Hash Table

A hash table stores key–value data pairs using a hash function. This allows it to achieve near constant-time lookup, insertion, and deletion of elements.

6. Graph

A graph stores data elements as nodes and edges that model relationships, networks, dependencies, and connections between them.

7. Tree

A tree is a connected, acyclic graph with just one path between any pair of vertices.

It has one node designated as the root, with each remaining node having exactly one parent and zero or more children.

8. Heap

A heap is a complete binary tree that satisfies the heap property, which is as follows for the two types of heaps:

  • Min Heap: The value of each parent node is less than or equal to the values of its children. This ensures that the element with the minimum value is at the root.

  • Max Heap: The value of each parent node is greater than or equal to the values of its children. This ensures that the element with the maximum value is at the root.

6. Algorithms

An algorithm is a step-by-step procedure or sequence of operations for solving a problem.

Algorithms manipulate data structures to solve problems.

An algorithm works agnostically of the programming language or hardware on which it is implemented.

A good algorithm has the following qualities:

  • Correctness: It should produce the right output for all valid inputs

  • Efficiency: It should use time and memory wisely. This is where the concept of Big-O comes in, which we will discuss in the upcoming section.

  • Clarity: It should be easy to understand, reason about, debug, and maintain.

  • Termination: It must always finish in a finite number of steps or have no infinite loops.

Some important algorithms in computer science are described as follows:

1. Recursive algorithms

Recursion is when a function calls itself to solve smaller instances of the same problem. Each recursive call works on a simpler case until reaching a base case that can be solved directly.

Some problems that can be solved using recursion include:

  • Calculating the factorial of a number

  • Computing the n-th Fibonacci number

  • Performing a Depth-first traversal of a tree

2. Sorting Algorithms

Sorting algorithms arrange elements in a specific order (ascending or descending).

3. Binary Search

This algorithm finds a target value in a sorted array by repeatedly halving the search interval.

This makes it more efficient than searching for the target value by comparing it to each element in an array one at a time (Linear search).

7. Big-O Notation

Time complexity measures how the runtime grows with input size.

Space complexity measures how the memory usage grows with input size.

The Big-O notation is used to describe the time and space complexities of an algorithm. This lets us understand how a system’s performance will scale when a particular algorithm is used.

Some common Big-O time complexities for commonly used operations and algorithms are as follows:

  • O(1) or Constant: Accessing an element in an array or hash table

  • O(log n) or Logarithmic: Binary search

  • O(n) or Linear: Iterating through an array or linear search

  • O(n log n) or Linearithmic: Merge sort, Heapsort

  • O(n²) or Quadratic: Bubble sort

  • O(2ⁿ) or Exponential: Finding the n-th Fibonacci number using recursion without memoization

  • O(n!) or Factorial: Brute-force approach to solving the Traveling Salesman Problem

Some common Big O space complexities for commonly used operations and algorithms are as follows:

  • O(1) or Constant: In‑place array update using a fixed number of variables

  • O(log n) or Logarithmic: Recursive binary search using the call stack

  • O(n) or Linear: Storing an array

  • O(n log n) or Linearithmic: Storing the root-to-node path for every node in a balanced binary tree

  • O(n²) or Quadratic: Storing an adjacency matrix for a graph

  • O(2ⁿ) or Exponential: Storing all subsets (the Power set) of an n‑element set

  • O(n!) or Factorial: Storing all permutations of ‘n’ elements at once

8. Programming Paradigms

Programming paradigms are models of programming that define how programs are structured and how solutions are expressed.

There are two main types of programming paradigms: Imperative and Declarative.

1. Imperative Programming

Imperative programs specify step-by-step instructions that explicitly control the flow and state.

The focus of these programs is on telling a computer how to solve a problem.

# Find sum of even numbers in Imperative style
total = 0

for num in range(1, 7):
    if num % 2 == 0:
        total += num  # Explicitly modify state

2. Declarative Programming

Declarative programs specify the desired result and let the system figure out the steps.

The focus of these programs is on telling a computer what outcome we want rather than how to reach it.

# Find sum of even numbers in Declarative style
total = sum(x for x in range(1, 7) if x % 2 == 0)

Imperative programming further includes:

1. Procedural Programming: This approach organizes code into procedures (functions) that operate on data.

2. Object-Oriented Programming (OOP): This approach organizes code into objects that bundle data and behavior.

The four pillars of OOP are important to know, and are as follows:

  • Encapsulation: Bundling data and methods together in a class while hiding internal details

  • Abstraction: Exposing only what’s necessary and hiding the complexity

  • Inheritance: Allowing child classes to reuse code from parent classes

  • Polymorphism: Letting the same method name have different behavior across different classes

(I use the mnemonic A PIE to remember them.)

Declarative programming includes a subtype called Functional Programming, which is worth knowing about.

The key principles of Functional Programming include:

  • Using pure functions that always return the same output for the same input and have no side effects (they don’t modify global variables)

  • Using immutable data, where existing data is never modified, and new data is created instead when required

  • Using first-class functions, which are functions treated as values, meaning they can be assigned to variables, passed as arguments, returned from other functions, and stored in data structures

9. Software Design Patterns

Building modern systems isn’t just about writing code that works. It rather involves writing code that works well, which means that it is maintainable, scalable, and flexible. This is where software design patterns come in.

Design patterns are reusable solutions that give templates for solving common software engineering problems in a structured way.

These patterns are frequently discussed in the context of Object-oritented programming (OOP) and come in three categories:

1. Creational Patterns: These focus on how objects are created

2. Structural Patterns: These focus on how objects are organized

3. Behavioral Patterns: These focus on how objects interact

10. SOLID Principles

SOLID principles are another important set of design principles for writing clean and maintainable OOP code.

The 5 SOLID principles are as follows:

  • Single Responsibility Principle: A class should do one thing only

  • Open/Closed Principle: Classes should be open for extension, closed for modification.

  • Liskov Substitution Principle: Child classes should be replaceable for their parent classes

  • Interface Segregation Principle: Many small interfaces are better than one large interface

  • Dependency Inversion Principle: Classes should depend on abstractions, not concrete implementations

The software design patterns described previously implement SOLID principles to achieve their goals.

11. Databases

Beyond program execution, data in a computer system must be stored for later retrieval. That is where Databases come in.

One of the commonly used classifications divides databases into two types:

1. Relational/ SQL databases: These databases organize data into tables with predefined schemas and use SQL (Structured Query Language) to query them. For example, PostgreSQL and MySQL.

2. Non-relational/NoSQL databases: These databases do not rely on fixed table schemas and store and query data in flexible ways. For example, MongoDB, Redis, and Cassandra.

Relational/ SQL databases use ACID transactions to maintain strict data integrity and relationships.

The acronym ACID stands for:

  • Atomicity: A transaction either completes entirely or fails, and no partial transactions occur.

  • Consistency: A system remains in a valid state before and after each transaction, as per all rules and constraints.

  • Isolation: Transactions running in parallel do so as if they’re the only ones executing. No two transactions interfere with each other’s intermediate states.

  • Durability: Once a transaction is committed, its changes are permanently saved and are unaffected by system failures.

On the other hand, NoSQL databases use BASE transactions to achieve high scalability and performance by relaxing consistency requirements.

The acronym BASE stands for:

  • Basically Available: The system remains operational even when parts of it fail, although some data may be temporarily inaccessible.

  • Soft State: Data can be temporarily inconsistent across different parts of the system. These temporary inconsistencies are resolved at a later time.

  • Eventual Consistency: Given sufficient time, all parts of the system synchronize and eventually converge to a consistent state.

12. Networking

Modern systems are built using multiple computers that communicate efficiently with each other, and this is where the concept of networking comes into play.

The Open Systems Interconnection (OSI) model standardizes network communication into seven layers, each with a specific function.

  1. Physical layer: Transmits raw bits over a physical medium, such as cables or signals

  2. Data Link layer: Organizes bits into frames and handles error detection

  3. Network layer: Routes packets across networks using IP addresses

  4. Transport layer: Ensures reliable data delivery with TCP or fast data delivery using UDP

  5. Session layer: Establishes and manages connections between applications

  6. Presentation layer: Translates data formats and handles encryption

  7. Application layer: Provides user-facing protocols like HTTP, FTP, and SMTP

TCP/IP is another network communication model that simplifies the OSI model into four practical layers:

  1. Network Access layer: Handles physical transmission and local network communication, such as Ethernet and WiFi

  2. Internet layer: Routes packets across different networks using IP addresses

  3. Transport layer: Manages end-to-end communication that ensures reliable delivery with TCP or fast delivery with UDP

  4. Application layer: Provides protocols for user-facing services like HTTP, DNS, and SSH

13. Multitasking Using Concurrency & Parallelism

As systems grow, they not only need to complete a task but also must perform multiple tasks simultaneously to handle the incoming load efficiently.

This is where the concepts of Multitasking come in, which include two important concepts:

1. Concurrency: This involves managing multiple tasks at the same time. These tasks may be interleaved on a single CPU core through Context switching, or they may run on multiple CPU cores/processors in parallel.

2. Parallelism: This involves executing multiple operations simultaneously using multiple CPU cores or processors.

Parallelism is a subset of Concurrency.

Although highly efficient, multitasking comes with its own challenges.

As multiple threads or processes access and manipulate shared data, this could lead to inconsistencies or even failures in producing results.

Synchronization primitives help solve this problem, and two of them that you must know about are:

  1. Mutex (Mutual Exclusion lock): This ensures that only one thread can access a shared resource at a time.

  2. Semaphore: This limits the number of threads that can access a resource simultaneously.

14. Cybersecurity

Building large interconnected systems increases the risk of data being accessed by unintended and even malicious parties.

Authentication, Authorization, and Encryption help protect against this:

  • Authentication is the process of verifying one’s identity, which can involve using a password, fingerprints, OTPs, etc.

  • Authorization is the process of determining what data one party can access or what permissions they have.

Encryption is the process of encoding information so that only authorized parties can access it. It involves passing a plaintext message through an encryption algorithm with a key and producing a ciphertext.

Decryption reverses this using the correct key.

Encryption algorithms are broadly classified as:

  1. Symmetric key cryptography: These algorithms use the same key for both encryption and decryption. For example, the Advanced Encryption Standard (AES).

  2. Asymmetric or Public Key Encryption: These algorithms use a public key for encryption and a private key for decryption. For example, the RSA (Rivest–Shamir–Adleman) cryptosystem.

15. Emerging Technologies

Beyond the classical computing stack, three technologies are pushing the boundaries of what computers can do. These are discussed below:

Artificial Intelligence

AI enables computers to learn from data without being explicitly programmed.

Machine Learning, a subset of Artificial Intelligence, has three main categories:

  • Supervised Learning: Involves learning from labeled data examples. For example, image classification.

  • Unsupervised Learning: Involves finding patterns in unlabeled data. For example, Clustering.

  • Reinforcement Learning: Involves learning through trial and error. For example, training a robot to segregate grocery items.

Blockchain

A Blockchain is a distributed, immutable ledger that records transactions across multiple computers. Each block in a blockchain contains transactions, a timestamp, and a cryptographic link to the previous block.

Blockchains enable trust in distributed systems by ensuring the following properties:

  • Decentralization: There is no central authority between the connected computers

  • Immutability: Past transactions/ records cannot be altered

  • Transparency: Everyone can see the same data whenever required

  • Security: There is protection of data using cryptographic algorithms

Quantum Computing

Quantum computers are among the most ambitious projects in computer science, using quantum mechanics to perform calculations impossible for classical computers.

While classical computers work with bits (0 or 1), Quantum computers work with Quantum bits or Qubits, which have two important properties.

  • Superposition: A qubit can exist in multiple states (0 and 1) simultaneously until measured.

  • Entanglement: Two qubits can become linked so that measuring one determines the state of the other instantly.

These properties allow the creation of various algorithms that can run on Quantum computers.

Once built, Quantum computers won’t replace classical computers but will tackle specific problems exponentially faster, leading to:

  • Faster chemical and drug discoveries

  • Efficiently solving currently hard to solve Optimization problems like the previously discussed Traveling Salesman Problem

  • Breaking current encryption methods
